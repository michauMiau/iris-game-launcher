# LibOVRPlatform64_1.dll shim semantics

**1. Scope and evidence.** This design is based on `platform_exports.txt` (native export names) and `game_ovr_names.txt` (names found in an IL2CPP game binary). The latter indicates the Unity SDK wrapper is present; it does not establish that every listed function is called by this title. Preserve exact native export names and ABI. In particular, wrapper names ending in `_Native` are not necessarily exported DLL names.

Prioritize the measured path: `ovr_Platform_InitializeStandaloneOculus` and/or `ovr_PlatformInitializeWithAccessToken`, result pumping, then `ovr_Entitlement_GetIsViewerEntitled`. The launcher path includes `ovr_ApplicationLifecycle_RegisterSessionKey`, `ovr_ApplicationLifecycle_GetLaunchDetails`, `ovr_Application_ExecuteCoordinatedLaunch`, and `ovr_Application_GetID`. Typed result accessors include `ovr_User_GetLoggedInUser`, `ovr_InstalledApplicationArray_GetElement`, and `ovr_ApplicationVersion_GetCurrentCode`.

The symbol lists do not specify prototypes, calling conventions, enum values, or ownership rules. Verify these against matching SDK headers or disassembly; do not infer the ABI from names.

**2. Minimum object-handle model.**

- Use a small pool of stable opaque records, returned as SDK-style handles. Each record should have a kind tag, lifetime state, scalar fields, stable string storage, and—where needed—references to child records. Start with records for messages, errors, users, launch details, application versions, installed-application arrays/items, and platform-initialize results. Keep records alive while Unity may still hold their handles; do not recycle a slot referenced by a queued message.
- Typed getters should return the stored fields or correctly typed child handles. For example, `ovr_Message_GetUser` returns a user payload; `ovr_Message_GetApplicationVersion` returns a version payload; `ovr_Message_GetInstalledApplicationArray` returns an array; and `ovr_Message_GetPlatformInitialize` returns an initialize payload read by `ovr_PlatformInitialize_GetResult`. A successful result must not have a missing required payload.
- Array `GetSize` returns the number of materialized elements. `GetElement` returns the correctly typed element at a valid zero-based index. Keep size, ordering, and backing elements consistent. For arrays with `HasNextPage`, return false when no further page exists; returning true means the corresponding next-page request (for example, `ovr_User_GetNextUserArrayPage`) must work. `ovr_InstalledApplicationArray` exports `GetSize` and `GetElement` but not `HasNextPage`, so return the complete local snapshot. Empty arrays have size zero; out-of-range access must not yield an arbitrary handle.
- String getters must return stable, NUL-terminated storage, not stack memory or a shared buffer overwritten by the next getter. This applies to fields such as `ovr_User_GetDisplayName`, `ovr_User_GetOculusID`, `ovr_ApplicationVersion_GetCurrentName`, `ovr_InstalledApplication_GetPackageName`, and `ovr_LaunchDetails_GetDeeplinkMessage`. Verify encoding and pointer ownership against the ABI.

**3. Unity result-pump protocol.**

- Associate each request with a request ID and a queued message record. Initialization must provide the initialize result in the shape the verified ABI expects; `ovr_Message_GetPlatformInitialize` and `ovr_PlatformInitialize_GetResult` expose its payload. A boolean initialized flag alone is insufficient if the wrapper expects a result object.
- When the wrapper’s result abstraction—often surfaced as `GetNextResult` or `WaitForResult`—waits for a request, deliver its matching completion. Implement the actual native queue surface used by the wrapper: `ovr_PopMessage` and, if routed through the Unity queue, `ovr_UnityGetMessageSync` and `ovr_UnityPutMessageOnQueue`. Match the verified timeout and ownership behavior. Empty nonblocking polls must use the ABI’s no-result form; blocking waits must not hang indefinitely. Preserve request IDs and queue order, and do not repeat consumed messages unless the SDK contract requires it.
- On success, `ovr_Message_IsError` is false. The managed `Result_IsStatusOK` abstraction should see a successful status, and `Result_GetError` should see no error in its expected shape. Those `Result_*` names are **not** in either supplied native export list. Native error-related exports include `ovr_Message_GetError`, `ovr_Error_GetCode`, `ovr_Error_GetMessage`, and `ovr_Error_GetDisplayableMessage`.
- `ovr_Entitlement_GetIsViewerEntitled` must complete through the result contract with the entitlement boolean. Do not confuse a request ID with the entitlement answer. A denial is a completed false result, not a missing message.
- Support `ovr_Platform_InitializeStandaloneOculus` and `ovr_PlatformInitializeWithAccessToken`; also handle `ovr_PlatformInitializeUnityWindows`, `ovr_PlatformInitializeUnityWindowsAsynchronous`, `ovr_PlatformInitializeWindows`, and `ovr_PlatformInitializeWindowsAsynchronous` if the wrapper selects them. Make repeated initialization idempotent unless the ABI specifies otherwise.

**4. Required values versus safe empty values.** “Non-NULL” applies only to pointer/handle returns. Request functions may return request IDs, enums, booleans, or void; verify each prototype before assigning sentinel values.

- **Must provide a valid handle or meaningful completion on the measured path:** initialization results; queued messages from `ovr_PopMessage` or applicable Unity queue functions when available; consistent message fields from `ovr_Message_GetRequestID`, `ovr_Message_GetType`, and `ovr_Message_IsError`; successful identity results via `ovr_User_GetLoggedInUser` and `ovr_Message_GetUser`; meaningful identity from `ovr_User_GetID`, `ovr_User_GetDisplayName`, and `ovr_User_GetOculusID`; and a completed true/false result from `ovr_Entitlement_GetIsViewerEntitled`.
- **Launcher and installed-app queries must be coherent if invoked:** `ovr_Application_GetID` must return the actual application ID. `ovr_ApplicationLifecycle_RegisterSessionKey` must accept the key according to its ABI, and `ovr_ApplicationLifecycle_GetSessionKey` / `ovr_ApplicationLifecycle_GetLaunchDetails` must return stable, consistent values. `ovr_Application_ExecuteCoordinatedLaunch` must use the expected request/result shape. For `ovr_Application_GetInstalledApplications` and `ovr_Application_GetVersion`, provide valid result payloads; installed-app array size/elements and `ovr_ApplicationVersion_GetCurrentCode` are especially important.
- **Values must agree when present:** user and launch fields (`ovr_LaunchDetails_Get*`); version fields (`ovr_ApplicationVersion_GetCurrentName`, `GetLatestCode`, `GetLatestName`, `GetReleaseDate`, `GetSize`); installed-app fields (`ovr_InstalledApplication_GetApplicationId`, `GetPackageName`, `GetStatus`, `GetVersionCode`, `GetVersionName`); and error fields (`ovr_Message_GetError`, `ovr_Error_GetCode`, `GetHttpCode`, `GetMessage`, `GetDisplayableMessage`) on failure.
- **NULL, zero, false, or empty is safe only when it represents an absent optional field, empty collection, unsupported feature, or documented failure.** Optional launch metadata includes deeplink, destination, lobby/match session IDs, room ID, and tracking ID (`ovr_LaunchDetails_GetDeeplinkMessage`, `GetDestinationApiName`, `GetLobbySessionID`, `GetMatchSessionID`, `GetRoomID`, `GetTrackingID`). Empty arrays may have size zero; arrays with no further pages should return `HasNextPage == false`. Return stable empty strings rather than NULL where the wrapper cannot tolerate NULL.
- Unused surfaces may initially return the ABI’s no-result form or a well-formed unsupported error **only if the title does not invoke them**. Examples include `ovr_Achievements_GetAllDefinitions`, `ovr_Matchmaking_Browse`, `ovr_Room_Get`, `ovr_CloudStorage_Load`, `ovr_IAP_GetProductsBySKU`, `ovr_Livestreaming_GetStatus`, `ovr_Net_Connect`, and `ovr_Voip_Start`. Do not use this fallback for initialization, entitlement, identity, launcher, or installed-app/version calls.

Zero can be a valid enum or boolean, but may also be an invalid ID or failed request handle. Confirm declarations before selecting numeric defaults.

**5. Launcher ownership data and crash risks.**

The launcher needs a per-install record containing:

- The numeric Oculus application ID for `ovr_Application_GetID`, plus package/application identifier and package name for `ovr_InstalledApplication_GetApplicationId` and `GetPackageName`.
- An explicit entitled/not-entitled decision for the active account and application. Distinguish missing metadata from an explicit denial; do not turn missing data into entitlement.
- Installed version code/name, latest version code/name if known, install status, and release date/size if queried. These feed `ovr_ApplicationVersion_Get*` and `ovr_InstalledApplication_GetVersionCode`, `GetVersionName`, and `GetStatus`.
- The registered session key and launch source/type, with optional deeplink, destination, room, lobby, match, and tracking metadata for `ovr_ApplicationLifecycle_GetLaunchDetails` and its getters.
- A stable nonzero user ID and profile fields such as display name/Oculus ID. Keep these consistent across `ovr_User_GetLoggedInUser`, `ovr_GetLoggedInUserID`, and result payloads.

The highest crash risks are mismatched array size/elements or wrong element types; dangling string pointers or reused mutable buffers; missing, stale, or mismatched result messages and payloads; pool records recycled while Unity retains their pointers; and any ABI mismatch in calling convention, width, signedness, enum, or return type.

**6. Implementation order.**

1. Verify critical prototypes, calling conventions, and result enum values; establish which initializer the wrapper invokes and how it consumes the result.
2. Implement exact exports with ABI-correct scalar and void returns.
3. Add stable object records, typed getters, string ownership, and bounded arrays; verify handle kinds, lifetimes, and index behavior.
4. Implement request IDs and the queue behavior for `ovr_PopMessage` and the Unity queue functions actually used; test polling, waiting, order, and consumption.
5. Implement initialization, user identity, and entitlement completions; ensure message error state and typed payloads agree.
6. Connect launcher data to application ID, session registration/details, coordinated launch, installed applications, and application version; verify values against the launcher record.
7. Trace the Unity wrapper from initialization through entitlement to main-menu entry, then add other service categories only when the trace shows they are needed.
